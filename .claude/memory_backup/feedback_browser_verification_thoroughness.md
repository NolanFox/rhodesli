Browser verification must check EVERY admin surface, not just the pages you changed. Session 111b checked only the landing page and Discoveries, then declared "browser verified." The Proposals page had 422 items and was completely unusable — no face thumbnails, no confirm/reject actions, raw distance numbers, wrong community header.

**Why:** Nolan called it "a disgrace" and "an embarrassment." Broken surfaces that the admin uses daily undermine trust in the entire system. The cost of checking each page is 30 seconds. The cost of missing a broken page is credibility.

**How to apply:**
1. After EVERY deploy, check ALL sidebar sections: New Matches, Discoveries, Help Identify, People, Photos, Compare, Proposals, Upload Review, Approvals, GEDCOM
2. For each: does it load? Does it show face thumbnails? Are there action buttons? Is the community header correct?
3. If ANY surface is broken, it's a P0 — don't proceed to harness docs
4. Never say "browser verified" without evidence for each surface
5. The verification checklist is not advisory — it's blocking
