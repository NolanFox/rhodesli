## Shape of the machine

This is a well-instrumented, heavily-audited solo-maintainer machine whose *process* artifacts have outgrown its *product*: the working code (app 7 MB of source, core, rhodesli_ml logic) is a small minority of a 20 GB tree, with 16 GB of stale worktrees whose size is itself caused by 854 MB of production data backups accidentally committed to git — the same production-data-in-git failure mode the project's own lessons file has cataloged six times. The safety harness is real (hooks all wired, CI-simulation tooling, allowlisted data files) but has two decorative layers: permission deny-rules neutered by `bypassPermissions`, and three plaintext live credentials parked in a local settings file that should be rotated today. Documentation is the project's superpower and its biggest tax — the two architecture docs injected into every context window describe a JSON-canonical system that stopped existing four months ago, the backlog's "active" section is roughly half trophies, and the 300-line doc cap is violated 95 times including by the 2,942-line decisions log that ML rules require reading. One focused cleanup session (worktree prune + backup untrack + secret rotation + the two @-imported doc rewrites) would reclaim ~18 GB and materially raise the signal-to-noise of every future session's context window.
